# Upload CV and Profile API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the single default user upload a CV PDF, store its extracted text in `user_profiles.cv_text`, and read/update the profile (GitHub issue #6).

**Architecture:** PDF extraction is a pure module `app/services/cv_parser.py` (no FastAPI imports). `app/api/routes_profile.py` validates the upload, calls the parser, and persists through a SQLAlchemy `Session` from `get_db`. Pydantic models live in `app/schemas/profile.py`. Errors use the existing `AppError` (body `{"error": {"code", "message"}}`).

**Tech Stack:** FastAPI 0.115, SQLAlchemy 2.0, PyMuPDF, pdfplumber, python-multipart, pytest + httpx `TestClient` with in-memory SQLite.

**Spec:** GitHub issue #6 and the design agreed in chat on 2026-10-24 (summarised in Global Constraints).

## Global Constraints

- Branch `feat/6-upload-cv`; one commit per task; PR body contains `Closes #6`.
- Single default user = the first `user_profiles` row ordered by `id` (seeded by migration 0002). No auth.
- Endpoints: `POST /api/v1/profile/upload-cv` (multipart field `file`), `GET /api/v1/profile`, `PUT /api/v1/profile`. Remove the `/ping` placeholder.
- Upload limits: extension `.pdf` (case-insensitive) AND content starts with `%PDF-`; max size `5 * 1024 * 1024` bytes. Wrong type → 415 `UNSUPPORTED_FILE_TYPE`; too large → 413 `FILE_TOO_LARGE`. Messages in Vietnamese.
- Read the upload in chunks and stop once it exceeds the limit (never load an oversized file fully).
- Extraction: PyMuPDF first, pdfplumber as fallback when PyMuPDF raises or yields no text. Normalised text shorter than `MIN_TEXT_CHARS = 20` → 422 `CV_NO_TEXT_LAYER` (scanned PDF; message suggests pasting text). Unopenable/encrypted PDF → 422 `CV_UNREADABLE`.
- Normalisation: `\r\n`/`\r` → `\n`; strip trailing spaces/tabs per line; collapse runs of spaces/tabs inside a line to one space; collapse 3+ newlines to 2; strip the whole text.
- Upload response: `{"char_count": int, "preview": str}` with `preview = cv_text[:500]`. The PDF file itself is not stored.
- `PUT /profile` fields (all optional, only provided fields change): `full_name` (≤100), `target_role` (non-blank, ≤100, stripped), `english_target` (≤50). `GET/PUT` return `{id, full_name, target_role, english_target, cv_text, has_cv}`.
- Tests run with `python -m pytest` from `backend/`; SQLite in-memory, `DATABASE_URL` set in `tests/conftest.py` before importing `app`.
- Run backend commands in the container when possible: `docker compose exec -T backend python -m pytest`; locally `cd backend && python -m pytest` is acceptable.

## Review Focus

- Empty-name/blank `target_role` in `PUT` returns 422, leaves the row unchanged. Pinned in Task 3.
- PUT with `{}` is a no-op returning the current profile. Pinned in Task 3.
- Upload of a `.pdf` named file whose bytes are not a PDF (e.g. a renamed `.txt`/`.exe`) → 415, `cv_text` untouched. Pinned in Task 6.
- File of exactly 5 MB is accepted by the size check; 5 MB + 1 byte → 413. Pinned in Task 6.
- Failed upload (scanned/corrupt) must not overwrite an existing `cv_text`. Pinned in Task 6.
- Missing `file` field → 422 with the standard error body. Pinned in Task 6.
